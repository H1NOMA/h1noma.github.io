# Push-уведомления о новых играх — развёртывание

Клиент (сайт) уже всё умеет: кнопка «Уведомления о новых играх» в аккаунте подписывает
устройство, а галочка «Оповестить» при создании игры дёргает эту функцию. Осталось один
раз задеплоить саму функцию — она и рассылает пуши.

## 1. Установить Supabase CLI (если ещё нет)
```
npm i -g supabase
supabase login
supabase link --project-ref xstrdpoxwbkbumigspdv
```

## 2. Задать секреты (VAPID-ключи)
Публичный ключ уже вшит в сайт (`VAPID_PUBLIC` в index.html). Приватный — только здесь,
никуда больше не выкладывать.
```
supabase secrets set \
  VAPID_PUBLIC="BJjgF7Dfj-PGEBho4AK_eec8YivMgnT5Oux8KdfLOx3sDcqpEBJ22tYzdsQ0fhx3S5IlRr-y3zTqsnOszzEpFI4" \
  VAPID_PRIVATE="<ПРИВАТНЫЙ_КЛЮЧ_ИЗ_ЧАТА>" \
  VAPID_SUBJECT="mailto:admin@komikdnd.ru"
```
(SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY платформа подставит сама.)

## 3. Задеплоить функцию
```
supabase functions deploy notify-game
```

Готово. Теперь при создании игры с галочкой «Оповестить» всем подписавшимся приходит пуш.

## ВАЖНО: выключить «Verify JWT» у функции
Новые проекты Supabase подписывают пользовательские токены ключами, которые шлюз
функций проверить не может → он возвращает `401 INVALID_CREDENTIALS` ещё до кода функции.
Авторизацию функция делает сама (проверяет dev-аккаунт), поэтому проверку на шлюзе нужно снять:

- **Дашборд:** Edge Functions → `notify-game` → вкладка **Details/Settings** → тумблер
  **«Verify JWT»** → **выключить**. (В некоторых версиях при деплое есть галочка
  «Verify JWT with legacy secret» — снять её.)
- **CLI:** это уже прописано в `supabase/config.toml` (`verify_jwt = false`) — просто
  переразверни: `supabase functions deploy notify-game`.

## Проверка
1. На телефоне: добавь сайт на главный экран (iOS 16.4+ — обязательно, иначе push не работает),
   открой из иконки, в аккаунте нажми «Включить уведомления», разреши.
2. С аккаунта hinoma/herr_teo создай игру с галочкой «Оповестить» — должно прийти уведомление.

## Своё облако (cloud.komikdnd.ru): ошибка «Vapid public key should be 65 bytes long»
Тест уведомлений отвечает `HTTP 500 … Vapid public key should be 65 bytes long when decoded` —
значит, в `docker-compose.override.yml` на сервере ключ VAPID обрезан, пуст или попал с кавычками.
Починка одной командой на сервере (спросит только приватный ключ):
```
bash <(curl -fsS https://komikdnd.ru/migrate/push.sh)
```
Скрипт вычищает ключи, публичный берёт из сайта, перекачивает свежую `index.ts`, пересоздаёт
контейнер `functions` и проверяет ответ. Если приватный ключ старой пары потерян — ответь `new`:
выпустит новую пару, публичный ключ надо вшить в `index.html` (`VAPID_PUBLIC`), а игрокам один
раз выключить-включить уведомления (сайт сам переоформит подписку под новый ключ).
Сама функция теперь не падает на битом ключе, а отвечает понятной ошибкой; публичный ключ
в окружении необязателен — копия вшита в `index.ts`.

## Заметки
- Рассылать может только аккаунт из списка `DEV` в index.ts (hinoma, herr_teo, arlissss) — держать в синхроне с `DEV_TAGS` на сайте.
- Мёртвые подписки (410/404) функция сама вычищает из `kv → push:subs`.
- Обновить VAPID-ключи потом = поменять и в index.html (`VAPID_PUBLIC`), и в секретах, и
  переподписать устройства.
