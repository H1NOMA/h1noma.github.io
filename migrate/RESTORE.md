# КОМИК · что делать, если… (памятка владельца)

Все команды ниже — копируй целиком. «На сервере» — после `ssh root@IP-сервера`.
«В PowerShell» — на своём компьютере с Windows (Пуск → PowerShell), **не** на сервере.
Вместо `IP` подставь адрес сервера, вместо `ТЕГ` — логин человека (например, `roman`).

Проверить, что защита базы включена (можно в любой момент, ничего не меняет), на сервере:

```bash
bash <(curl -fsS https://komikdnd.ru/migrate/push.sh) check
```

В конце должно быть **«Итог: защита базы включена ✓»**. Красный итог — запусти `push.sh` без `check`
(на вопрос о ключе — Enter; если он ответит «ключ битый, а новый не введён» — `new`); не помогло — покажи
вывод программисту.

## 1. Что хранить у себя (не только на сервере)

Данные сайта (таблица `kv`) GitHub копирует сам, раз в сутки, в ветку `backups` — только за последнюю неделю
(копии старше 7 дней удаляются сразу; копии на сервере — `kv-before-restore-*`, `auth-*` — тоже, кроме последней копии аккаунтов).
А вот эти файлы есть **только на сервере** — умрёт сервер, умрут и они:

| Файл на сервере | Что в нём | Без него |
|---|---|---|
| `/opt/supabase/docker/.env` | ключи облака (JWT-секрет, анон- и сервисный ключ, пароли) | новые ключи → править сайт |
| `/opt/supabase/docker/docker-compose.override.yml` | VAPID-ключ пушей | устройства переподпишутся сами, но не сразу |
| `/root/komik-cloud-info.txt` | логин/пароль панели Studio | пароль лежит и в `.env` |
| `/root/auth-ДАТА.sql.gz` (раз в месяц) | аккаунты игроков (логины + хэши паролей) и состав команды | **все** регистрируются заново |

Раз в месяц (и после каждой настройки сервера, и после того, как кого-то снял с команды или добавил — пункты 6–7):

1. На сервере — свежая копия аккаунтов (и команды: кто в ней и к какому аккаунту привязан):
   ```bash
   bash <(curl -fsS https://komikdnd.ru/migrate/restore.sh) accounts
   ```
   Скрипт сам напечатает команду `scp` для скачивания.
2. В PowerShell — забрать всё в папку `komik-backup` (у каждого файла — полное имя: путь, который
   кончается на `\`, PowerShell ломает, если в имени твоей папки пользователя есть пробел):
   ```powershell
   mkdir $HOME\komik-backup -Force
   scp root@IP:/opt/supabase/docker/.env $HOME\komik-backup\komik-env.backup
   scp root@IP:/opt/supabase/docker/docker-compose.override.yml $HOME\komik-backup\komik-override.backup
   scp root@IP:/root/komik-cloud-info.txt $HOME\komik-backup\komik-cloud-info.txt
   scp root@IP:/root/auth-2026-09-26.sql.gz $HOME\komik-backup\auth-2026-09-26.sql.gz
   ```
   (дату в последней строке — ту, что напечатал скрипт, в обоих местах).

Это **секреты**: не пересылай их в чаты, не клади в GitHub. Хорошее место — зашифрованная флешка
или облако с двухфакторным входом.

## 2. Сервер умер (или переезд на новый)

1. Купи новый VPS: Ubuntu 22.04 или 24.04, от 2 ГБ памяти. Запиши его IP.
2. У регистратора домена (Timeweb → домен → DNS) поменяй запись `cloud.komikdnd.ru` (тип A) на новый IP.
   **Сайт шёл с умершего сервера** (настроен `site.sh`)? Тогда сразу же верни сайт на GitHub Pages — он откроется
   (пока без облака), и команды ниже, которые качаются с `komikdnd.ru`, заработают:
   * запись A для `komikdnd.ru` (@) — четыре адреса GitHub: `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153` (адрес сервера из неё убери);
   * запись `www` — CNAME `h1noma.github.io`.

   Не хочешь ждать DNS — те же команды можно брать прямо с GitHub: вместо `https://komikdnd.ru/migrate/…`
   пиши `https://raw.githubusercontent.com/H1NOMA/h1noma.github.io/main/migrate/…`.
3. В PowerShell — положи сохранённые файлы на новый сервер (имена важны). Первая строка — если сервер
   переустановлен на том же адресе (или адрес тебе уже попадался): компьютер забудет старый «отпечаток»
   сервера, иначе `scp` и `ssh` откажут с «REMOTE HOST IDENTIFICATION HAS CHANGED» (ответ «not found» —
   тоже нормально). На первое подключение спросит `Are you sure you want to continue connecting (yes/no)?` —
   напиши `yes`.
   ```powershell
   ssh-keygen -R IP
   scp $HOME\komik-backup\komik-env.backup root@IP:/root/komik-env.backup
   scp $HOME\komik-backup\komik-override.backup root@IP:/root/komik-override.backup
   scp $HOME\komik-backup\auth-2026-09-26.sql.gz root@IP:/root/auth-2026-09-26.sql.gz
   ```
4. На сервере — установка (10–20 минут; повторный запуск безопасен):
   ```bash
   bash <(curl -fsS https://komikdnd.ru/migrate/setup.sh)
   ```
   Она сама возьмёт прежние ключи, вернёт данные сайта из самой свежей копии GitHub,
   загрузит аккаунты и состав команды (снятые остаются снятыми, добавленные — в команде) и привяжет права.
5. На сервере — пуши и итоговая проверка (на вопрос о ключе — Enter; если `komik-override.backup` не было —
   `new`):
   ```bash
   bash <(curl -fsS https://komikdnd.ru/migrate/push.sh)
   ```
   В конце — «Итог: защита базы включена ✓».
6. По желанию — защита самого сервера: `bash <(curl -fsS https://komikdnd.ru/migrate/harden.sh)`.
7. Открой сайт, войди, проверь листы и расписание.
8. Сайт — снова с сервера (быстро и без VPN): `bash <(curl -fsS https://komikdnd.ru/migrate/site.sh)`. Он выложит
   сайт, подскажет, какие записи DNS поменять (`komikdnd.ru` и `www` — на IP сервера), дождётся этого и включит https.

Если чего-то из сохранённого нет:
* нет `komik-env.backup` — ключи будут новые: `setup.sh` в конце скажет, какой ключ вписать в `index.html`
  и `.github/workflows/backup-kv.yml` (это правка кода);
* нет `komik-override.backup` — на вопрос о ключе в `setup.sh` нажми Enter, а в `push.sh` (шаг 5) напиши `new`:
  будет новая пара ключей пушей, устройства переподпишутся сами, когда откроют сайт;
* нет дампа аккаунтов — всем придётся зарегистрироваться заново. **Сразу** после установки сам зарегистрируй
  `hinoma`, `herr_teo`, `arlissss` на сайте, потом запусти `push.sh` — он привяжет им права команды;
* дамп аккаунтов старый, сделан до того, как в него стал попадать состав команды (`setup.sh` об этом предупредит), —
  после установки повтори пункты 6–7 для тех, кого снимал с команды или добавлял.

## 3. Кто-то испортил данные

Посмотреть, за какие дни есть копии (копия делается раз в сутки около 06:17 по Москве, хранятся последние 7 дней):

```bash
bash <(curl -fsS https://komikdnd.ru/migrate/restore.sh)
```

Вернуть **один ключ** на выбранную дату (лучше так — остальное не трогается):

```bash
bash <(curl -fsS https://komikdnd.ru/migrate/restore.sh) 2026-09-25 comik:games:v1
```

Вернуть **всю таблицу**: `bash <(curl -fsS https://komikdnd.ru/migrate/restore.sh) 2026-09-25`.

Скрипт покажет, что изменится, и спросит — напиши `да`. Строки, которых нет в копии, не удаляются.
Всё, что поменялось в этом ключе после копии, пропадёт.

Перед записью скрипт сохраняет текущую таблицу и в конце печатает команду отмены:
* вернул **один ключ** — отмена тоже про один ключ: `restore.sh /root/kv-before-restore-….json.gz comik:games:v1`;
* вернул **всю таблицу** — отмена (`restore.sh /root/kv-before-restore-….json.gz`) вернёт к состоянию до
  восстановления **все** ключи: всё, что игроки успели сделать после него (записи на игры, доска, листы), пропадёт.
  Если не так вернулся один ключ — отменяй только его, дописав ключ в конец команды.

| Ключ | Что это |
|---|---|
| `comik:games:v1` | расписание и запись на игры |
| `comik:tracker:shared:v1` | доска ходов |
| `comik:chars:ТЕГ` | листы персонажей игрока |
| `comik:news:v1`, `comik:archive:v1`, `comik:hero:v1` | новости, архив, приветствие |
| `comik:img:ХЭШ` | фото карточек, новостей и портреты (с 28.10.2026 — отдельными строками; в карточке — ссылка `kvimg:ХЭШ`) |
| `push:sub:ТЕГ` | пуш-подписки игрока (до 29.10.2026 — общая `push:subs`) |

Строки `comik:img:…` никогда не удаляй: на них ссылаются карточки и листы, в том числе из старых копий.
Возврат архива или листов на любую дату фото не портит — старые копии хранят фото внутри себя, новые ссылаются
на строки, которые никуда не деваются.

**После возврата расписания (`comik:games:v1`) попроси всех закрыть и заново открыть сайт (все вкладки).**
Открытая вкладка помнит удалённые игры до перезагрузки: вернувшиеся игры она не покажет, а при следующей
записи на игру снова их удалит. Листы (`comik:chars:ТЕГ`) скрипт возвращает со свежей отметкой времени —
на устройствах игроков они сами заменят и удаление, и более поздние правки этих листов.

Если испорченное возвращается само — сначала проверь, что все закрыли и заново открыли сайт (для расписания —
это самая частая причина). Если и после этого возвращается — значит, кто-то продолжает портить: закрой
регистрацию (пункт 4) и позови программиста.

### Откат строки из журнала (с точностью до одной правки, последние 7 дней)

С 29.10.2026 сервер записывает каждую правку: кто (тег), когда и какое значение было **до** неё. Игроки общие
строки испортить уже не могут (меняют только свою запись и свои карточки), так что это — на случай ошибки команды.
Посмотреть последние правки ключа:

```bash
docker exec -it supabase-db psql -U postgres -d postgres -c "select id, at, op, tag, old_size, new_size, old_value is not null as can_back from kv_history where key = 'comik:games:v1' order by at desc limit 30"
```

Найди строку с испортившей правкой и верни значение, которое было до неё (`ID` — число из первого столбца,
`can_back` должно быть `t`):

```bash
docker exec -it supabase-db psql -U postgres -d postgres -c "update kv set value = (select old_value from kv_history where id = ID and key = 'comik:games:v1') where key = 'comik:games:v1' and exists (select 1 from kv_history where id = ID and key = 'comik:games:v1' and old_value is not null)"
```

Сам откат тоже попадает в журнал — его можно отменить так же. Доску ходов журнал не хранит (её переписывает каждый
тап по ХП), большие строки (листы, архив) — не чаще раза в 15 минут; для них — копия за сутки (`restore.sh` выше).

## 4. Срочно: закрыть регистрацию

Когда портит кто-то, кто сам зарегистрировался. На сервере:

```bash
cd /opt/supabase/docker && sed -i 's/^DISABLE_SIGNUP=.*/DISABLE_SIGNUP=true/' .env && docker compose up -d auth
```

Уже зарегистрированные входят как прежде; кнопка «Регистрация» на сайте будет выдавать ошибку.
Новых игроков заводишь сам: Studio (`https://cloud.komikdnd.ru`, логин и пароль — в `/root/komik-cloud-info.txt`)
→ Authentication → **Add user** → Create new user: e-mail `ТЕГ@komikdnd.ru` (тег — 4–32 знака: латиница, цифры, `_`),
пароль от 8 символов, галочка **Auto Confirm User**. Логин и пароль передай игроку.

Открыть регистрацию обратно — та же команда с `DISABLE_SIGNUP=false`. `push.sh` эту настройку не трогает.

## 5. Сменить пароль игроку (или себе)

Сменить пароль и выкинуть все входы этого аккаунта — на сервере:

```bash
docker exec -it supabase-db psql -U postgres -d postgres
```

```sql
update auth.users set encrypted_password = extensions.crypt('НОВЫЙ-ПАРОЛЬ', extensions.gen_salt('bf', 10))
 where email = 'ТЕГ@komikdnd.ru';
delete from auth.sessions where user_id = (select id from auth.users where email = 'ТЕГ@komikdnd.ru');
\q
```

Первая строка должна ответить `UPDATE 1`. Уже открытая вкладка проживёт ещё до часа, потом выйдет.
Меняй пароль, только если уверен, что пишет сам игрок (новый пароль лучше передать голосом или лично).

## 6. Человек уходит из команды

**Аккаунт не удаляй**: его логин освободится, и кто угодно зарегистрируется под ним.
Вместо этого — случайный пароль, выход со всех устройств и снятие прав. На сервере:

```bash
docker exec -it supabase-db psql -U postgres -d postgres
```

```sql
update auth.users set encrypted_password = extensions.crypt(encode(extensions.gen_random_bytes(24), 'base64'), extensions.gen_salt('bf', 10))
 where email = 'ТЕГ@komikdnd.ru';
delete from auth.sessions where user_id = (select id from auth.users where email = 'ТЕГ@komikdnd.ru');
update public.devs set uid = '00000000-0000-0000-0000-000000000000' where tag = 'ТЕГ';
\q
```

Строку из `public.devs` **не удаляй**: `push.sh` при каждом запуске возвращает в список `hinoma`, `herr_teo`,
`arlissss` и заново привязал бы права к ещё живому аккаунту. Нули в `uid` — «снят с команды»,
так и покажет `push.sh check`. Права в базе пропадают сразу (открытая вкладка — до часа).
Потом сделай свежую копию аккаунтов (пункт 1): состав команды хранится в ней, и при переезде
на новый сервер снятый останется снятым.

Ещё его логин записан в коде: `DEV_TAGS` в `index.html` (режим команды на сайте) и `DEV` в
`supabase/functions/notify-game/index.ts` (рассылка пушей). Убрать оттуда — правка кода, нужен программист.

## 7. Новый человек в команде

1. Человек **сам** регистрируется на сайте (логин = его тег).
2. На сервере добавь тег в команду:
   ```bash
   docker exec supabase-db psql -U postgres -d postgres -c "insert into public.devs(tag) values ('ТЕГ') on conflict (tag) do update set uid = null"
   ```
   (эта же команда возвращает в команду того, кого раньше сняли).
3. Запусти `push.sh` (на вопрос о ключе — Enter). Он привяжет права к аккаунту и в проверке покажет `ТЕГ ✓`.
   Если там написано «привязан к аккаунту (заведён …)» с незнакомой датой — это не тот человек:
   сними его (пункт 6) и разберись.
4. Сделай свежую копию аккаунтов (пункт 1) — чтобы новый человек остался в команде и после переезда.

Порядок важен: пока аккаунта нет, права не привязываются, и логин команды никто не может «занять».
Чтобы у человека был режим команды на сайте и рассылка пушей — его тег нужно добавить в `DEV_TAGS`
(`index.html`) и `DEV` (`notify-game/index.ts`): правка кода, нужен программист.

## 8. Сайт с нашего сервера (`site.sh`)

С 28.10.2026 сайт можно отдавать не с GitHub Pages, а с того же сервера, что и облако (в России): без VPN так
быстрее, и файлы идут сжатые brotli. GitHub остаётся источником: правки попадают в `main`, сервер забирает их сам
раз в минуту (таймер `komik-site.timer`).

* Включить (или обновить настройку): `bash <(curl -fsS https://komikdnd.ru/migrate/site.sh)` — скрипт выложит сайт
  и попросит поменять DNS в Timeweb: запись A для `komikdnd.ru` — IP сервера (четыре адреса GitHub `185.199.…` удалить),
  `www` — CNAME `komikdnd.ru`. Дождётся смены, включит https и проверит.
* Проверить: `bash <(curl -fsS https://komikdnd.ru/migrate/site.sh) check`.
* Сервер лежит, а сайт нужен прямо сейчас — верни DNS на GitHub (пункт 2), сайт откроется оттуда (без облака).
  Когда сервер оживёт и DNS снова укажет на него, ничего делать не нужно.
* Совсем вернуться на GitHub Pages: DNS как в пункте 2, затем на сервере
  `bash <(curl -fsS https://komikdnd.ru/migrate/site.sh) off`.
* Новая версия не появляется: `journalctl -u komik-site -n 20` — что пишет обновление (обычно «GitHub не ответил» —
  сайт остаётся прежним и догонит, как только GitHub ответит). Выложить заново: `komik-site-sync force`.
