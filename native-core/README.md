# КОМИК · native-core

Чистое **ядро логики** КОМИКа, вынесенное из `index.html` в независимые ES-модули —
фундамент для будущего мобильного приложения (React Native / Expo) без переписывания правил.

> Это **не** трогает текущий сайт. Модули существуют отдельно; веб-версия продолжает работать как есть.
> Их задача — переиспользоваться в нативном приложении один-в-один.

## Зачем

Самая нудная и рискованная часть переезда в приложение — не кнопки, а **игровая математика**
(характеристики, бонус мастерства, спасброски, навыки, заклинания, спасброски от смерти).
Здесь она уже:

- отвязана от DOM (никаких `document`, `localStorage`, рендера);
- без зависимостей — работает в React Native, Node и любом бандлере;
- покрыта тестами.

Значит в приложении её можно подключить сразу, а силы бросить на визуал.

## Что внутри

| Модуль | Что даёт |
|---|---|
| `abilities.js` | модификаторы, бонус мастерства, спасброски/навыки, покупка очков, список навыков |
| `dice.js` | чистые броски: `rollDie`, `rollDice`, `rollPool` (rng подставляется — легко тестировать) |
| `spellcasting.js` | классы-заклинатели, заговоры/известные/подготовленные, совокупный уровень мультикласса и таблица ячеек |
| `deathSaves.js` | машина состояний спасбросков от смерти (успех/провал/крит/стабилизация/смерть) |
| `settings.js` | порядок и названия сеттингов, ядро SRD, **дизайн-токены тем** (цвета/шрифты из CSS) |
| `character.js` | `deriveSheet(char)` — из объекта персонажа считает весь лист одним вызовом |
| `taxonomy.js` | категории архива, справочник источников, ступени редкости, блокировки по сеттингам |
| `archive.js` | чистые фильтры/фасеты/поиск/сортировка + сборка ядра под сеттинг (`queryArchive`, `coreForSetting`) |
| `data/extract.mjs` | локальный инструмент выгрузки встроенных JSON-блоков в ассеты (`node native-core/data/extract.mjs`) |
| `data/loadArchive.js` | адаптер источника карточек: нормализация + единый `loadArchive(source)` |
| `index.js` | общий вход: `import { ... } from './native-core'` |

### Слой данных (`data/`)

Единая абстракция хранилища — веб и приложение работают через один интерфейс, логика от бэкенда независима.

| Модуль | Что даёт |
|---|---|
| `data/keys.js` | ключи хранилища (те же, что в вебе) + разделение общее/личное |
| `data/session.js` | теги, разработчики, права (`isDev`, `canManageGame`, `seatsLeft`, `assimVisible`) |
| `data/sync.js` | `mergeById`, `mergeByFreshness` (надгробия), `optimisticApply` (идемпотентная запись в стол) |
| `data/store.js` | `createMemoryStore`, `createLayeredStore` (облако+локаль с таймаутом), `supabaseKvStore(client)` + Realtime |
| `data/board.js` | ключи досок (`boardKey`), слияние карточек стола, активная доска игрока |
| `data/repositories.js` | репозитории: персонажи, игры (запись/кик/права), новости, «стол» (публикация/подписка) |

Supabase-клиент **внедряется снаружи** — в ядре нет зависимости от `@supabase/supabase-js`:

```js
import { createClient } from '@supabase/supabase-js';
import { supabaseKvStore, createLayeredStore, createMemoryStore, gamesRepo } from './native-core/data';

const cloud = supabaseKvStore(createClient(url, anonKey));
const store = createLayeredStore({ cloud, local: createMemoryStore() });   // в RN local → обёртка над AsyncStorage
const games = gamesRepo(store);
await games.signup('g1', session, { name: 'Боб' });
```

### Про данные архива (важно про лицензии)

Сам **контент карточек в ядро не копируется**. Часть описаний основана на не-SRD источниках,
поэтому мы не плодим его в новых файлах. Схема такая:

- **логика** архива (фильтры/фасеты/поиск/ядро под сеттинг) — здесь, в `archive.js`, DOM-free;
- **структура** (категории, источники, редкость) — в `taxonomy.js`;
- **данные** остаются там, где уже лежат (встроены в `index.html`). Локально их можно выгрузить в
  ассеты командой `node native-core/data/extract.mjs` — но эти `.json` в `.gitignore` и в репозиторий
  не попадают. В приложении карточки подаются тем же адаптером `loadArchive(source)` из бандла или API.

## Как пользоваться

```js
import { deriveSheet, rollPool, themeFor, multiclassSlots } from './native-core/index.js';

// лист персонажа (тот же объект, что хранит веб-версия в Supabase)
const sheet = deriveSheet(character);
// sheet.pb, sheet.maxHp, sheet.mods, sheet.saves, sheet.skills, sheet.spells

// бросок пула кубов
const { total, crit, parts } = rollPool({ 20: 1, 6: 2 });

// тема сеттинга для React Native (цвета совпадают с вебом)
const t = themeFor('classic');   // { bg, surface, accent, txt, ... }
```

В React Native токены темы кладутся в провайдер темы, `deriveSheet` заворачивается в `useMemo`.

## Тесты

```bash
node native-core/__tests__/core.test.mjs
```

Без зависимостей и тест-раннеров — просто node. Проверяет модификаторы, мастерство, кубы (на
детерминированном rng), заклинания, мультикласс, спасброски от смерти, сборку листа и токены темы.
