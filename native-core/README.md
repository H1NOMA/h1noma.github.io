# КОМИК · native-core

Чистое **ядро логики** КОМИКа, вынесенное из `index.html` в независимые ES-модули —
фундамент для будущего мобильного приложения (React Native / Expo) без переписывания правил.

> Это **не** трогает текущий сайт. Модули существуют отдельно; веб-версия продолжает работать как есть.
> Их задача — переиспользоваться в нативном приложении один-в-один.

## Зачем

Самая нудная и рискованная часть переезда в приложение — не кнопки, а **игровая математика**
(характеристики, бонус мастерства, спасброски, навыки, заклинания, спасброски от смерти).
Здесь она уже:

- отвязана от DOM (никаких `document`, `localStorage`, рендера);
- без зависимостей — работает в React Native, Node и любом бандлере;
- покрыта тестами.

Значит в приложении её можно подключить сразу, а силы бросить на визуал.

## Что внутри

| Модуль | Что даёт |
|---|---|
| `abilities.js` | модификаторы, бонус мастерства, спасброски/навыки, покупка очков, список навыков |
| `dice.js` | чистые броски: `rollDie`, `rollDice`, `rollPool` (rng подставляется — легко тестировать) |
| `spellcasting.js` | классы-заклинатели, заговоры/известные/подготовленные, совокупный уровень мультикласса и таблица ячеек |
| `deathSaves.js` | машина состояний спасбросков от смерти (успех/провал/крит/стабилизация/смерть) |
| `settings.js` | порядок и названия сеттингов, ядро SRD, **дизайн-токены тем** (цвета/шрифты из CSS) |
| `character.js` | `deriveSheet(char)` — из объекта персонажа считает весь лист одним вызовом |
| `index.js` | общий вход: `import { ... } from './native-core'` |

## Как пользоваться

```js
import { deriveSheet, rollPool, themeFor, multiclassSlots } from './native-core/index.js';

// лист персонажа (тот же объект, что хранит веб-версия в Supabase)
const sheet = deriveSheet(character);
// sheet.pb, sheet.maxHp, sheet.mods, sheet.saves, sheet.skills, sheet.spells

// бросок пула кубов
const { total, crit, parts } = rollPool({ 20: 1, 6: 2 });

// тема сеттинга для React Native (цвета совпадают с вебом)
const t = themeFor('classic');   // { bg, surface, accent, txt, ... }
```

В React Native токены темы кладутся в провайдер темы, `deriveSheet` заворачивается в `useMemo`.

## Тесты

```bash
node native-core/__tests__/core.test.mjs
```

Без зависимостей и тест-раннеров — просто node. Проверяет модификаторы, мастерство, кубы (на
детерминированном rng), заклинания, мультикласс, спасброски от смерти, сборку листа и токены темы.

## Что дальше (дорожная карта переезда)

Уже готово — **ядро правил**. Следующие слои, по порядку:

1. **Данные архива** — вынести встроенные JSON-блоки (`core-data` и т.п.) в отдельные ассеты/модуль,
   добавить чистые фильтры/фасеты/поиск (сейчас частично завязаны на DOM).
2. **Слой данных** — обёртка над Supabase (аккаунты, персонажи, расписание, живой «стол»/трекер),
   переиспользуемая и вебом, и приложением.
3. **UI на React Native** — экраны (лист → архив → трекер → новости/расписание → ГМ),
   анимации/заставки на `react-native-skia`/Reanimated, стеклянные эффекты, рамки сеттингов.
4. **Платформенное** — нативные пуши (APNs/FCM), deep links для `?g=…`, удаление аккаунта,
   развилка оплаты, иконки/сплэши.

Ядро из этой папки закрывает пункт «правила» полностью и переиспользуется на всех следующих шагах.
